## 已确认的事实

| 项目 | 基线 / 决策 |
|---|---|
| 个人钱包 | `billing_wallets.user_id`；个人消费归 `usage_events.billed_user_id`，不按工作区所有成员汇总 |
| 平台身份 | 独立全局 `platform_role_assignments`；团队角色保持租户内语义 |
| 旧权限来源 | 旧 `system_admin`、`tenant_admin` 角色映射和 `ADMIN_EMAILS` 不自动迁移为平台授权 |
| 管理读权限 | 受平台能力与事务上下文共同约束；运营读取不启用 `app.is_system_admin` |
| 财务写权限 | 赠送和增减积分均要求 `platform:billing:adjust`；支付敏感写要求 `platform:billing:manage` |
| 模型管理 | 模型、线路、连接、凭证沿用现有 Gateway 表和服务；凭证不读回明文 |
| 数据库验证 | disposable DB 中使用非 owner、非 BYPASSRLS 的角色检查；不能据此断言生产连接角色已正确设置 |
| 请求与任务 | 历史 runtime 调用日志不能直接当作物理请求或最终生成成功；未知关联保留未知 |

- 平台授权策略、认证、API、实际 PostgreSQL 身份与并发保护测试已执行。
- 跨工作区用户/任务/个人消费读取已验证；运营不能修改钱包余额、支付状态或受保护的平台账号。
- 模型、价格、连接、凭证 RLS 的直连写入检查已执行，并发现、补齐原本无 RLS 的全局表。

- 具体执行命令、最终计数和未通过项以 `PROJECT_RECORD.md` 的最新实施记录为准。

## 上线前仍需核查

这些项目只能用目标环境真实状态确认；不得将本地测试推断为已完成。

1. 实际部署 commit/image 与 `schema_migrations` 中 filename、version、checksum、执行时间。
2. API/Worker 的数据库登录是否为普通运行角色；迁移账号与运行账号是否分离；是否存在超级用户或 BYPASSRLS。
3. 经负责人核实的平台管理员 UUID、已验证邮箱、账号状态、授权理由；不得批量晋升团队管理员。
4. 个人钱包切换是否完成，近期 usage 与 ledger、支付入账是否一致；历史缺失字段数量。
5. 两个以上工作区、普通用户、运营、超级管理员的真实登录与 API 权限矩阵。
6. 生产数据量和目标机器配置，用量/调用查询性能与旧画布线路、资产访问回归。

查询与备份输出只保存脱敏统计和审核结论，不保存密码、完整数据库 URL 或真实凭证。
