# 视频节点生成模式输入判定设计

日期：2026-08-10
状态：已确认设计，待编写实施计划
适用范围：TapFlow v2 Flow 画布视频生成节点

## 1. 背景

视频节点的生成模式必须随输入素材变化。当前用户可以把上游节点、资产库素材或上传素材接入视频节点，但模式菜单还需要明确表达哪些模式适用于当前输入、哪些模式被禁用，以及禁用原因。

本设计以 LibTV 风格的模式菜单为交互参考：五种模式始终显示；不可用项置灰；鼠标悬浮或键盘聚焦时显示具体原因。

## 2. 目标

- 统一统计上游连线、节点内资产和直接上传的图片、视频、音频输入。
- 文本节点只提供提示词，不影响媒体模式判定。
- 按媒体输入拓扑严格计算五种模式的可用状态。
- 当前模式因输入变化失效时，自动切换到推荐模式，并只提示一次。
- 两张图片默认使用“图片参考”，首尾帧由用户主动选择。
- 当前模型不支持输入要求的模式时，不自动更换模型，阻止生成并给出换模提示。
- 前端菜单判定和服务端生成前校验使用相同语义，不能依赖前端绕过校验。

## 3. 非目标

- 不新增视频生成模式。
- 不根据文本节点数量推断模式。
- 不自动删除超出限制的输入素材。
- 不因输入变化自动切换视频模型。
- 不把媒体 URL、Blob、File、base64 或临时签名 URL 写入 flow draft。

## 4. 输入归一化

模式判定接收统一的媒体输入集合，来源包括：

- 上游节点连线输出；
- 节点内从资产库选择的素材；
- 节点内直接上传并持久化的素材。

每条输入至少包含：

```ts
{
  source: { kind: "upstream" | "asset", id: string },
  mediaKind: "text" | "image" | "video" | "audio",
  order: number,
}
```

同一素材按稳定身份去重：

```txt
upstream:<nodeId>
asset:<assetId>
```

归一化后的统计值为：

```ts
{
  textCount: number,
  imageCount: number,
  videoCount: number,
  audioCount: number,
}
```

`textCount` 只用于提示词合并和提示词校验，不参与模式矩阵。

## 5. 输入拓扑模式矩阵

输入层先于模型层判断。输入层只判断素材组合是否符合产品模式语义。

| 当前媒体输入 | 文生视频 | 图生视频 | 首尾帧 | 图片参考 | 全能参考 |
| --- | --- | --- | --- | --- | --- |
| 无图片、视频、音频，含或不含文本 | 可用 | 禁用 | 禁用 | 禁用 | 禁用 |
| 1 张图片 | 禁用 | 可用 | 可用 | 可用 | 可用 |
| 2 张图片 | 禁用 | 禁用 | 可用 | 可用 | 可用 |
| 3 张及以上图片 | 禁用 | 禁用 | 禁用 | 可用 | 可用 |
| 包含任意视频 | 禁用 | 禁用 | 禁用 | 禁用 | 仅全能参考 |
| 包含任意音频 | 禁用 | 禁用 | 禁用 | 禁用 | 仅全能参考 |
| 图片与视频或音频混合 | 禁用 | 禁用 | 禁用 | 禁用 | 仅全能参考 |

说明：

- 文生视频要求没有任何媒体输入；文本节点本身不会使其他模式可用。
- 图生视频要求恰好一张图片。
- 首尾帧接受一到两张图片；一张图只有首帧，两张图按顺序作为首帧和尾帧。
- 图片参考要求至少一张图片，不表达时间顺序。
- 全能参考要求至少一个媒体输入，可混合图片、视频和音频；具体模型还可施加更严格的媒体类型和数量限制。
- 如果输入不满足某模式，模式项仍显示在菜单中，但不可点击。

## 6. 首尾帧角色

首尾帧模式使用统一输入顺序确定角色：

```txt
[image A]             -> A = first_frame
[image A, image B]    -> A = first_frame, B = last_frame
```

输入被删除或重排后必须重新标准化：

- 仅剩一张图片时，剩余图片变为 `first_frame`；
- 两张图片时，排序第 0 项为 `first_frame`，排序第 1 项为 `last_frame`；
- 三张及以上图片使首尾帧模式不可用，但不得删除多余图片；
- 首尾帧卡片显示“首帧”和“尾帧”角色标签，而不是普通序号。

首尾帧模式不自动作为两张图片的默认模式。两张图片的默认模式是图片参考，用户需要主动选择首尾帧来表达时间顺序。

## 7. 模型能力交集

输入拓扑判定与模型能力判定分为两层：

```ts
inputAllowed = 输入拓扑满足模式契约
modelSupported = capabilities.supportedModes 包含该模式
enabled = inputAllowed && modelSupported
```

实际模式菜单状态由两层结果共同决定：

```ts
type VideoModeAvailability = {
  mode: VideoGenerationMode;
  inputAllowed: boolean;
  modelSupported: boolean;
  enabled: boolean;
  reasonCode: string | null;
  message: string | null;
};
```

当前模型不支持某模式时：

- 不自动切换模型；
- 模式项保持可见并置灰；
- Tooltip 说明“当前模型不支持该生成模式”；
- 如果输入拓扑只允许该模式，则保留该模式作为输入语义，阻止生成；
- 生成前必须再次执行服务端能力校验。

示例：Veo 当前不支持全能参考，但用户接入了视频：

```txt
输入层允许：all_reference
模型层支持：不支持 all_reference
当前模式：自动设置为 all_reference
生成结果：阻止生成，提示更换模型
```

如果存在多个输入允许模式，应优先选取当前模型支持的模式。例如两张图片时，当前模型不支持首尾帧但支持图片参考，则自动使用图片参考。

## 8. 自动切换规则

自动切换只在当前模式变为不可用时发生。当前模式仍然可用时保持不变，避免用户手动选择的模式被输入变化打断。

输入变化后的推荐模式：

| 输入状态 | 推荐模式 |
| --- | --- |
| 无媒体 | `text_to_video` |
| 1 张图片 | `image_to_video` |
| 2 张图片 | `image_reference` |
| 3 张及以上图片 | `image_reference` |
| 存在视频或音频 | `all_reference` |

模型能力会对推荐结果做二次筛选：

1. 先计算输入层允许集合；
2. 保留当前模式（如果仍在允许集合且模型支持）；
3. 当前模式失效时，从推荐模式开始选择第一个同时满足输入层和模型层的模式；
4. 如果没有任何模型支持的模式，设置为输入语义的唯一或首选模式，并显示模型不兼容阻止状态。

自动切换提示必须按输入签名去重，建议签名包含：

```txt
input signature + old mode + new mode
```

提示示例：

- `检测到 1 张图片，已切换为图生视频`；
- `检测到 2 张图片，已切换为图片参考`；
- `检测到视频输入，已切换为全能参考`。

同一输入变化不能因为 React 重渲染、草稿恢复或模型目录刷新重复弹出提示。

## 9. 菜单和 Tooltip

五个模式项始终渲染，不可用项不隐藏。

- 可用项：正常文字、图标和选中态；
- 输入不满足：置灰，悬浮显示数量或媒体类型原因；
- 模型不支持：置灰，悬浮显示模型能力原因；
- 当前已选但模型不支持：保留选中态并增加不兼容标识；
- 点击不可用项不改变模式；
- 不使用原生 `disabled` 阻断 Tooltip，使用 `aria-disabled` 和菜单层交互；
- Tooltip 支持鼠标悬浮、键盘聚焦和 Escape/外部点击关闭。

建议文案：

| 模式 | 不可用原因 | 文案模板 |
| --- | --- | --- |
| 文生视频 | 存在媒体 | 已连接媒体输入，无法使用纯文生视频 |
| 图生视频 | 图片数不为 1 | 当前图片数量为 {count} 个，图生视频需要 1 个 |
| 首尾帧 | 图片数不在 1～2 | 当前图片数量为 {count} 个，首尾帧需要 1～2 个 |
| 图片参考 | 没有图片 | 图片参考模式至少需要 1 张图片 |
| 图片参考 | 存在视频或音频 | 已连接视频或音频，请使用全能参考 |
| 全能参考 | 没有媒体 | 全能参考模式至少需要 1 个媒体输入 |
| 任意模式 | 模型不支持 | 当前模型不支持该生成模式 |

## 10. 生成前校验

前端模式菜单、生成按钮和服务端必须使用同一套语义。

前端负责：

- 实时刷新模式项状态；
- 自动切换模式；
- 显示 Tooltip、轻提示和输入角色；
- 在提交前显示第一条阻止原因。

API/worker 负责：

- 重新统计安全的输入引用；
- 校验模式与媒体数量、媒体类型和角色顺序；
- 校验当前 route 的 `supportedModes`、媒体上限和计费配置；
- 非法组合直接拒绝，不创建免费执行任务；
- 不信任前端传入的临时 URL 或媒体类型声明。

## 11. 测试矩阵

必须覆盖：

- 无输入、仅一个文本节点、多个文本节点；
- 1、2、3 张图片；
- 图片数量超过模型上限；
- 仅视频、仅音频、图片加视频、图片加音频；
- 上游素材和节点内资产的去重；
- 首尾帧单图、双图、删除首图、删除尾图和重排；
- 每个禁用项的动态 Tooltip 文案；
- 当前模式仍有效时不自动切换；
- 当前模式失效时按优先级自动切换；
- 自动切换提示只出现一次；
- 当前模型不支持时不自动换模型；
- 前端与服务端对相同输入组合给出一致结果。

## 13. 验收标准

- 无媒体输入时，只有文生视频可用；
- 1 张图片时，图生视频、首尾帧、图片参考、全能参考可用；
- 2 张图片时，图片参考、首尾帧、全能参考可用，默认图片参考；
- 3 张及以上图片时，仅图片参考和全能参考可用；
- 任意视频或音频输入时，仅全能参考可用；
- 文本节点数量不改变以上结果；
- 不可用项悬浮能解释具体原因；
- 模式失效时自动切换并只显示一次提示；
- 模型不兼容时不自动切换模型，生成被阻止；
- 首尾帧单图和双图角色正确；
- 前后端校验一致，非法输入无法绕过前端执行。
