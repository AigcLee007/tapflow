# 平台模板中心与整组执行设计

## 背景

当前画布支持把节点打组、解组和布局，但“整组执行”尚未真正限定执行范围；组工具栏中的“创建模板”目前只生成剪贴板 JSON，模板列表则读取服务端 `flow_templates` 数据。需要将两项能力收敛为清晰、可计费、可审计的 v2 产品流程。

## 目标

1. 平台管理员可以在专用模板管理页面和管理项目中创建、测试、发布、下架官方模板。
2. 所有已登录用户可以查看已发布模板，并将模板作为独立副本插入自己的项目。
3. 模板可以声明少量、明确的输入项，用户插入时完成配置。
4. 用户对画布组执行时，只执行该组内的可执行节点，并按依赖关系调度。
5. 每次整组执行都要先确认范围、输入、预计积分和潜在错误。

## 非目标

- 首版不开放普通用户创建或发布模板。
- 首版不实现模板市场、评分、分享链接或跨租户团队模板。
- 首版不支持条件分支、动态数组输入、嵌套对象输入或模板内嵌套模板。
- 不把 base64、Blob、data URL、永久签名 URL 或 File 对象写入模板图或画布草稿。

## 产品信息架构

平台管理员入口：

- `/admin/templates`：模板列表、搜索、分类筛选、状态筛选和操作入口。
- `/admin/templates/new`：创建模板管理项目。
- `/admin/templates/:templateId/editor`：模板画布编辑器。

普通用户入口：

- 现有画布左侧“模板列表”抽屉，仅展示已发布官方模板。
- 用户点击“插入”后先完成模板输入配置；提交后将模板复制到当前项目。

模板状态：

- `draft`：管理员可编辑，普通用户不可见。
- `testing`：管理员可运行测试，普通用户不可见。
- `published`：所有已登录用户可查看和插入。
- `archived`：禁止新插入，历史项目中已经存在的副本不受影响。

模板是平台级资源，不绑定租户。后台写操作必须使用 `admin:system` 权限；普通用户读取和插入继续使用现有认证、租户上下文和 `flow:read` / `flow:update` 权限。

## 模板创建与发布流程

平台管理员在专用管理项目中使用普通 Flow 画布搭建节点和连线：

1. 创建节点、配置模型/参数并连接内部依赖。
2. 选中可复用节点并打组。
3. 点击“保存为模板”，填写名称、描述、分类、封面和使用说明。
4. 在节点字段旁通过“设为模板输入”开关标记可配置字段。
5. 保存为草稿，系统记录源图和规范化模板图。
6. 在模板编辑器中执行测试，显示输入校验、节点状态、错误和预计积分。
7. 测试通过后发布一个稳定版本；发布后的版本供普通用户插入。
8. 后续编辑产生新草稿/新版本，不覆盖已发布版本；发布新版本后只影响之后的插入。
9. 下架模板后不允许新的插入，但不删除历史使用记录，也不改变用户已有副本。

模板保存内容至少包括：

- 节点和内部 edges。
- 节点相对位置、尺寸、类型、模型和生成参数。
- 输入定义 `input_schema`。
- 标题、描述、分类、封面资产 ID、使用说明。
- 状态、版本、发布人、发布时间和审计字段。
- 预计积分或可计算预计积分所需的模型/定价信息。

媒体字段只保留 `assetId` 作为权威来源；插入时重新获取可用的预览/签名 URL。

## 模板输入项

首版支持四类输入：

1. 文本。
2. 图片、视频、音频素材。
3. 单选枚举。
4. 数字。

每个输入项包含：显示名称、类型、是否必填、默认值、目标节点 ID、目标字段路径，以及类型对应的枚举值或数字范围。

管理员在节点字段旁标记输入项。发布前必须保证：目标节点存在、字段路径有效、输入 ID 唯一、必填项有明确校验规则、素材输入只引用资产字段。

用户插入模板时：

- 无输入项的模板可以直接插入。
- 有输入项的模板先打开配置窗口；必填项未完成或值不合法时不能提交。
- 素材输入使用资产库选择器，不上传到模板 JSON。
- 提交后系统复制节点和内部连线，生成新节点 ID，替换输入值并将图插入当前画布中心。
- 插入后的节点属于用户当前项目，用户可以继续修改，不与官方模板建立可变引用。
- 系统记录实际插入的模板 ID 和版本，便于统计与审计。

## 整组执行语义

“整组执行”只针对当前选中的组节点及其直属子节点。首版不自动递归执行嵌套组；若出现嵌套组，应在执行前提示管理员/用户并阻止提交，直到明确处理方式。

执行范围：

- 组内支持执行的文本、图片、视频等节点纳入本次组任务。
- 组内没有生成提示词、模型线路或必要输入的节点不纳入执行，并在确认窗口中列为配置问题。
- 组外节点只提供已有结果；不自动触发组外节点。
- 组外输入不存在、尚未生成或已失效时，阻止执行并指出依赖节点。

调度方式：

- 入度为零且互不依赖的节点并行启动。
- 有内部边依赖的节点仅在所需上游成功后启动。
- 某节点失败时，依赖该节点的下游标记为跳过/阻塞；不依赖它的分支继续。
- 组任务展示总状态、已完成/运行中/失败/跳过数量和每个节点状态。
- 支持“重试失败项”；成功节点不重复运行，重试仍遵循相同依赖和计费规则。

每次点击“整组执行”必须先显示确认窗口，内容包括：

- 将执行的节点数量和节点列表。
- 并行分支及依赖顺序摘要。
- 组外输入读取情况。
- 缺失输入、模型不可用、定价缺失、参数错误等阻断项。
- 预计积分和当前可用余额。
- “开始执行”和“取消”操作。

存在阻断项或余额不足时，“开始执行”不可用。取消不创建任务、不预留积分。确认后，服务端按现有 billing 流程对每个实际执行节点 reserve，成功 settle，失败 refund/release，并使用幂等键避免重复扣费。

## 数据与 API 方向

在现有 `flow_templates` 能力上扩展，而不是另建一套独立模板系统。建议增加：

- `status`。
- `version`。
- `input_schema` JSONB。
- `published_at`、`published_by`。
- 稳定的源图/发布图字段或等价版本记录。

后台 API 需要覆盖：

- 管理员创建/更新草稿。
- 管理员读取、测试、发布、下架模板。
- 普通用户列出已发布模板、读取发布图、记录插入使用。

API 必须验证平台管理员权限、输入 schema、模板状态和图结构；普通用户不得通过 API 读取草稿或修改官方模板。模板图查询和插入都要进行服务端权限检查。

组执行 API/运行时需要支持显式执行范围，例如 `group_id` 或规范化的 `node_ids`，不能用无参数的全 Flow 执行来模拟组执行。服务端仍需基于当前草稿、租户和项目权限重新校验范围，不能信任前端传来的节点集合。

## 错误处理与安全边界

- 未登录或无租户上下文：使用现有 v2 auth/tenant 失败响应。
- 非平台管理员访问管理 API：返回 403，不泄露模板草稿内容。
- 模板图非法、输入字段失效或发布校验失败：拒绝保存/发布并指出具体字段。
- 模型线路不存在、定价不存在或凭证不可用：执行前 fail closed，不创建免费任务。
- 任何 provider 密钥、加密凭证、原始 Authorization header 都不得进入模板图、前端响应、日志或截图。
- 模板下架采用状态变更，保留历史版本、使用记录和用户副本。

## 验收标准

模板中心：

- 平台管理员可创建草稿、配置输入、保存、测试、发布和下架。
- 普通用户只能看到已发布模板，并可完成输入配置后插入。
- 插入模板会生成独立节点/边 ID，位置不覆盖现有画布，媒体仍由资产 ID 驱动。
- 发布新版本和下架不会修改已有用户画布。

整组执行：

- 只运行当前组内合法节点；组外节点不会被自动触发。
- 外部结果缺失时，确认窗口明确阻止启动。
- 每次执行都先确认，显示预计积分和执行范围。
- 内部独立分支并行，依赖节点按顺序运行。
- 失败分支正确阻塞下游，独立分支继续，失败项可重试且不会重复成功节点。
- reserve/settle/refund 和幂等行为有后端测试覆盖。

## 分阶段范围

第一阶段：模板管理页、模板专用画布、草稿/发布/下架、四类输入、用户模板插入、真实组范围执行、执行确认和积分预估。

第二阶段：版本比较与回滚、模板使用统计、模板复制、自动封面、条件输入和动态参数。
