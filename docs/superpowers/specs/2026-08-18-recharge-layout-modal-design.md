# 充值套餐单行布局与支付弹窗设计

## 目标

优化账单页充值体验：桌面端四组套餐保持同一行展示；点击“立即充值”后，将二维码和支付状态放入视口居中的弹窗，不再把支付内容推到页面下方。

## 交互范围

- 桌面端：充值套餐网格使用四列等宽布局，卡片高度稳定，推荐套餐仍保留推荐标识。
- 响应式：较窄视口降为两列或单列，避免横向溢出；移动端不强制四列。
- 支付弹窗：创建订单后立即展示居中模态层，采用“扫码优先”单列收银台，二维码居中显示。
- 支付方式：明确展示“微信支付”和“当前仅支持微信支付”，不显示无效的支付方式选择器。
- 支付信息：弹窗只保留二维码、应付金额、到账积分和支付状态，移除嵌套的“支付状态”大卡片。
- 模态层：背景遮罩、关闭按钮、Escape 和遮罩点击关闭；页面背景锁定滚动。
- 支付状态：沿用现有轮询、成功/失败状态、重试、返回套餐和查看账单动作。

## 组件边界

- `RechargePanel` 只负责套餐网格和选择回调，不持有支付展示状态。
- `RechargeDialog` 负责模态层定位、尺寸约束、滚动锁定和支付/套餐视图切换。
- `PaymentStatusPanel` 负责二维码及支付状态内容，在弹窗中保持现有支付流程。

## 验证

- 组件测试确认四列布局 token 和四张套餐卡同时渲染。
- 账单页测试确认创建订单后二维码出现在 dialog 内，而不是账单页正文区域。
